# 蛇类照片每日更新

维护 `weijintao123/snake-library`，来源仅为 https://snake.pictureknow.com/topics ，网站为 https://weijintao123.github.io/snake-library/ 。读取 [项目与恢复说明](references/project.md) 后工作；线上仓库是当前基线，旧迁移包只提供历史上下文。

## 每次运行

1. 读取仓库 README、`scripts/sync_catalog.py`、工作流、`docs/species_catalog.json`、`docs/topic_photo_index.json`、存在时的 `docs/topic_sync_state.json`。记录基线提交、图片数、成功截止点，检查最新 Actions 的抓取日志，不能只看绿色状态。
2. 用户已登录时，优先通过内置浏览器读取话题卡片的原图、话题ID与物种字段。新电脑若返回首页或登录页，请用户在该浏览器登录；不索取、提取或导出密码、Cookie、令牌，不读浏览器凭据存储。浏览器登录不等于配置 GitHub Secret。
3. 对可见话题照片核验确有蛇和实际图片。按站点ID、学名、中文名唯一匹配；字段冲突、非蛇、无图、明显物种标注冲突或无法确认则跳过并记录原因。站点名称是来源标注，不能声称经过专家鉴定。只采话题，保持152种目录，不自动增种或改毒性。
4. 持续滚动/翻页到已知记录或页面终点；记录实际覆盖范围。DOM只返回5条或缺发布时间时，只报告“可见记录导入”，不声称已完整补齐过去若干天，不推进API成功截止点。不得伪造时间、图片或话题ID。
5. 将已核验记录保存为仓库 `scripts/pending_topic_photos.json`，格式见参考。同步脚本位于 `assets/sync_catalog.py`，它是2026-10-18的兼容升级版；先与当前仓库比较再应用，不覆盖后来改进。脚本依赖 Python 3.12 和 Pillow。手工导入：`python scripts/sync_catalog.py --pending-only`；已安全配置环境变量时发现最近三天候选：`python scripts/sync_catalog.py --days 3`，输出 `scripts/topic_review_queue.json`，逐张核验后将允许导入的记录标记 `visual_verified: true` 写入待办，再用 `--pending-only` 导入。发现过程只生成待审队列，不自动归档或推进截止点。输入仅包括已核验的蛇照片；图片解码验证不能代替内容核验。
6. 优先下载原图，保留其他内容参数；原图返回 OSS InvalidObjectState 时，可尝试网页实际使用的仅格式转换全尺寸 `?x-oss-process=image/format,webp`，在记录中填写 `download_url` 和 `original_unavailable`，不冒称原文件，不自行截图或压缩。先规范化URL，再按内容SHA-256去重，先查全局哈希再写入，跨URL/物种也只保留一个规范路径。已有图只增不删、不覆盖；保存原图URL、SHA、物种、话题ID和来源。
7. 检查新增文件能解码、哈希和索引一致，重复运行新增数应为0。同步本地镜像时，已知URL也要补齐镜像；本地成功、推送成功、部署成功分别核验，不能用本地 `cloud_saved` 证明推送完成。失败保持可重试，不推进未完成抓取的截止点。
8. 用户请求更新该图库已涵盖相关新增照片及索引发布。提交前审查差异只涉及图库相关文件；不得运行旧工作流的历史删除步骤。无数据或索引变化不做空提交。发布后等待对应提交的Pages部署，核对线上索引、新增图HTTP访问与页面显示。更新失败保留本地成果和待重试说明。

## 每日使用与自动运行

用户每天说“更新蛇照片”即可执行一次完整流程。Skill本身不带调度器。仓库已有北京时间09:00计划（UTC `0 1 * * *`，实际运行可延迟）；不要仅因“我每日更新”再创建重复自动化。只有用户明确要求新建/修改定时任务时才配置调度。

GitHub无人值守发现需要用户在仓库设置中配置 `SNAKE_TOPIC_TOKEN`。不要将浏览器会话复制给Actions，不在日志、代码、skill或zip中放凭据。未配置或过期必须明确报告发现未完成；不能默默跳过后把部署成功当作抓取成功。完整分页到指定起点；站点总话题数超过500不等于本次截断，只有实际取满500仍未到达窗口起点时才报告缺口。重复页、缺时间或无法覆盖窗口时不认证完整性。默认最近三天；用户要求补齐更长中断时用明确窗口，不能把最近三天结果当作整个中断期。
